RONDA ONE 0.7.3 — STABILITY FIRST / QUEUE-FIRST

OBJETIVO
Tirar geração de carrossel e rondas do request HTTP longo. O navegador apenas cria a tarefa e acompanha o progresso; o processamento roda em Cloudflare Queue.

ANTES DE SUBIR O wrangler.jsonc DESTA VERSÃO, CRIE NO CLOUDFLARE:
1. ronda-one-round-jobs
2. ronda-one-intelligent-jobs
3. ronda-one-jobs-dlq

Cloudflare Dashboard -> Storage & databases / Queues -> Create queue.

Depois envie o PATCH ao GitHub. O deploy criará os bindings:
- ROUND_JOBS_QUEUE -> ronda-one-round-jobs
- INTELLIGENT_JOBS_QUEUE -> ronda-one-intelligent-jobs

Os dois consumidores usam batch 1 e até 3 tentativas. Falhas terminais podem ir para ronda-one-jobs-dlq.

CUSTO MVP
Cloudflare Queues está disponível no Workers Free com 10.000 operações/dia. Uma mensagem normalmente usa 3 operações (write/read/delete). Com a ronda a cada 5 minutos + geração editorial normal, o MVP fica muito abaixo desse limite.

TESTES APÓS DEPLOY
1. /api/platform/status deve mostrar queues.round=true e queues.intelligent=true.
2. /ronda/api/health deve mostrar intelligentReading.queueReady=true e executionMode="cloudflare-queue".
3. Execute uma ronda.
4. Gere um carrossel: a UI deve receber a tarefa rapidamente e acompanhar progresso por polling.
5. Fechar o modal não cancela o processamento; ao reabrir/tentar novamente, o job persistido no D1 continua rastreável.

ASSETS
A 0.7.3 também deixa app.js e demais assets estáticos fora de /ronda/* Worker-first. Isso reduz CPU e evita a tela sem CSS/JS observada na 0.7.2.
